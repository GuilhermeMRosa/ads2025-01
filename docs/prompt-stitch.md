# Prompt — Google Stitch (esqueleto inicial das páginas)

Prompt em texto corrido, pronto pra colar no [Google Stitch](https://stitch.withgoogle.com/), usado para gerar o esqueleto visual inicial das páginas do site. O resultado é só ponto de partida — ajustado depois no próprio Stitch ou manualmente no Figma.

---

Crie o esqueleto visual de um site web responsivo, pensado mobile-first, para a sala de Análise e Desenvolvimento de Sistemas de uma faculdade, que serve como central de informações e colaboração da turma. Use componentes no estilo shadcn/ui, com uma paleta de cores simples baseada em branco como fundo predominante e vermelho como cor de destaque/ação, estruturada de um jeito fácil de trocar depois (poucas variáveis de cor centralizadas, nada de cor espalhada e hardcoded pelo layout). Não use nenhuma imagem, foto, ilustração ou mockup de imagem em lugar nenhum da interface — toda comunicação visual deve vir de tipografia, cor, espaçamento, ícones simples e cards, nunca de imagem. O layout deve ser extremamente modular, com componentes pequenos e reutilizáveis (cards de item, listas, cabeçalhos de seção, badges de status, formulários), já que o site vai crescer e ser refatorado bastante no futuro, então evite blocos de página monolíticos. Gere o esqueleto das seguintes telas, sem se preocupar ainda com dado real, apenas com a estrutura e hierarquia visual de cada uma: uma página inicial que funciona como um painel de destaque do dia, mostrando a aula atual ou próxima e o próximo evento importante; uma página de horários com uma grade semanal visual por dia e matéria; uma página de matérias que mostra tanto as matérias do semestre atual quanto uma grade completa histórica de todos os semestres já cursados; uma página de provas e atividades, listando itens com data de entrega, matéria, tipo e descrição, com destaque visual pra datas futuras versus vencidas; uma página de calendário da API/estágio mostrando os dados de empresa, P2 e M2; uma página de vagas de emprego em formato de lista de cards, com campos opcionais como link, fonte, local e requisitos, e indicação visual de vaga aberta ou expirada; um mural de avisos com posts curtos e informais em formato de feed; uma seção de blog separada do mural, com posts mais longos, categorizados por tema, mostrando contagem de visualizações e curtidas; uma página de calendário unificado que cruza provas, calendário da API e avisos num único calendário visual; uma página de pedidos ao representante de turma, em formato de lista simples com status aberto ou resolvido; uma página de perfil do usuário chamada "minhas solicitações", mostrando o status de tudo que a pessoa já submeteu, com indicação de pendente, aprovado ou rejeitado e o motivo quando rejeitado; uma tela de login e outra de cadastro, essa última pedindo nome, e-mail, senha e o papel que a pessoa está solicitando; e uma tela de fila de aprovação/moderação, usada por quem modera, listando itens pendentes com opção de aprovar ou rejeitar e campo de motivo. Pense em um cabeçalho e navegação consistentes entre todas as páginas, adaptados pra tela pequena primeiro (menu provavelmente colapsado/inferior no mobile), e mantenha a hierarquia visual simples e limpa, sem floreio, priorizando legibilidade e facilidade de uso rápido entre uma aula e outra.
